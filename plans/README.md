### 003 — accepted deviation

Measured after: rail row **36px**, tab **33px**, table row **44px**. The plan's
gate asked for 36/36/44. The tab stops 3px short: `padding={4}` overshot it to
49px, and the only remaining routes were a hardcoded height on a Sanity UI
component or CSS fighting styled-components. Neither is worth 3px. The plan's
purpose — ending the 25/25/44 spread — is met.

### 003 — a defect in the plan, not the executor

The plan prescribed `.nav-item { min-height: 36px }`. That rule shipped, and
computed to `0px`. Sanity UI is styled-components: its generated class has
identical specificity (0,1,0) and is injected into `<head>` *after* the static
stylesheet, so source order decided it. The fix is a doubled selector,
`.nav-item.nav-item`, with a comment saying why. **Any future plan that adds CSS
targeting a Sanity UI component must account for this** — it is the second time
in this project's history that a static rule lost to Sanity UI's runtime CSS.

## Findings considered and rejected

- **A search or filter box in the rail**: not worth doing. 18 projects across
  two collapsible groups is not a scanning problem, and the fleet table already
  has a filter. Plan 007 explores the keyboard-driven version of this instead.
- **Replacing Sanity UI with another component library**: rejected. Looking
  like Sanity Studio is a deliberate design goal of this app, recorded in
  `README.md`; the earlier session explicitly declined Tailwind/shadcn for the
  same reason.
- **Colour-coding rail rows by project health**: deferred, not rejected. It is
  a design decision nobody has made, and plan 006's maintenance note records it
  as a follow-up if the draft count proves useful.
- **Rewriting git history to purge the committed identifiers**: rejected in
  plan 005. They are public identifiers, not credentials; history rewriting on
  a repo that may already be cloned is disproportionate to the benefit.
- **Splitting the organization row's dual behaviour** (label navigates and
  expands, chevron only expands): deferred to a design decision rather than
  planned. Plan 004 makes the behaviour *announced*; changing it is a separate
  call, recorded in that plan's maintenance notes.
